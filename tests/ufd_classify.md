# 硬直差が3F以上ずれている技の仕分け

最新の main（`74264ca`）で `python3 tests/compare_ufd.py` を再実行した。照合は 650 項目、一致 563、不一致 87（`tests/ufd_compare.md` の表と同じ）。このうち硬直差（攻撃側。画面のガード有利の符号を反転した値）の差が 3F 以上なのは 20 件。

データの出典は検証窓シート（`raw/<gid>.csv`）。UFD は候補を出すための参考で、シートに無い硬直や全体Fは入れていない。画面の有利は次のルールで選んでいる。

- 多段は通常の最終段（ラベルが Hit / 連 / 〆 / 派生）
- 同じ段のガード硬直は大きい方
- ラベルに「（前）」と「（後）」が両方ある技は正面だけ。その中の最終段
- ヒット時のバウンド行がある空中は、その全体Fから硬直を引く
- アルセーヌの段は主数値にしない

攻撃側の硬直差 = −（全体F − 発生F − ガード硬直）。空中は −（着地隙 − ガード硬直）。画面に出るガード有利は符号が逆（マリオ下スマは画面 +21F、照合の「本サイト -21」）。

## (c) 判断できない（6）

下スマッシュで、シートの行名が Hit 1 と Hit 2 だけのもの。角度も「前」「後」も備考に無い。多段の最終段なら Hit 2、正面なら先に出る段、のどちらもシートの文言だけでは決められない。

Hit 1 を正面として大きい硬直で計算した値は参考で、コードには入れていない。ロイ・クラウド・ルキナは、その値が UFD の先頭と一致する。マリオは硬直が 1F 違い（シート7、UFD 8）、マルスは根元側が UFD 先頭で先端側は 2F 違い。ジョーカーは発生が 4F しか離れておらず、つながる二段の可能性が残る。全体Fもシート45に対し UFD 51。

| キャラ | シート Hit 1 を採った場合（攻撃側 / ガード側） | 今の画面 = Hit 2（攻撃側 / ガード側） | UFD |
|---|---|---|---|
| マリオ | 5F・硬直7・全体43 → -31 / +31 | 14F・硬直8 → -21 / +21 | -30/-20（硬直8/9。First/Second） |
| マルス | 6F・硬直8（6が三つと8）・全体55 → -41 / +41 | 21F・硬直11 → -23 / +23 | -43/-41/-26/-23 |
| ロイ | 6F・硬直10・全体62 → -46 / +46 | 21F・硬直11 → -30 / +30 | -46/-49/-30/-33 |
| クラウド | 8F・硬直3・全体49 → -38 / +38 | 21F・硬直8 → -20 / +20 | -38/-20 |
| ルキナ | 6F・硬直7・全体55 → -42 / +42 | 21F・硬直10 → -24 / +24 | -42/-24 |
| ジョーカー | 12F・硬直8・全体45 → -25 / +25 | 16F・硬直8 → -21 / +21 | -24/-20（全体Fは51。硬直8/9） |

正面だと決めなかった理由:

- 同じシートで方向を書くときは「（前）」「（後）」や「前方」「後方」になる。スティーブ下スマは「〆1（前）」を既に主数値にしている。照合対象外だが、ネス下スマは「後方」のあとに「前方」と書いてあり、先に出る段が正面とは限らない。
- つながる多段は最終段で UFD の公開値と合う。ピーチ下スマは UFD が Multi/Final の -21 だけで、画面の Hit 7 と一致する。ピカチュウ下スマも最終段の -39 だけを出していて画面と一致する。Hit 1 を常に正面にすると、これらの最終段が崩れる。
- したがって Hit 1 / Hit 2 の下スマを一括で前側にする一般ルールは、シートから置けない。個別の技に UFD の数字を写すこともしない。

## 照合の読み方

`tests/compare_ufd.py` は UFD の advantage の先頭の数だけを比べる。ベヨネッタ上強のように、画面が UFD の2つ目（最終段）と一致していても、先頭と違えば不一致一覧に残る。
